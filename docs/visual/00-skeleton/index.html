Project skeleton

Folders, tooling and placeholders before any feature. Every future file already has a home, and the same checks run on your laptop and in CI.

1. How the packages depend on each other

  classDef core fill:#eef0ff,stroke:#4f46e5,color:#16181d;

Arrows mean "imports from". Everything depends on @sta/shared; nothing depends on the apps. This keeps the AI layer reusable from scripts and tests.

2. Folder map

apps/

web (UI), api (HTTP). Things you start and open.

packages/

shared, ai, db. Libraries the apps import.

services/

Python helpers: py-evals (Ragas), py-doc-parser (Docling).

evals/ · data/

promptfoo tests · raw (gitignored), sample, knowledge-base.

infra/

docker (local), terraform (Azure), helm (Kubernetes).

docs/

brief, architecture, runbook, task map, learning, visual.

Problems and fixes

SymptomComment-only .ts files can fail to compile
CauseNo import/export → TypeScript treats it as a global script
FixmoduleDetection: "force"
Lesson: understand each tsconfig option instead of copying it.
SymptomNext.js can't use @sta/shared TypeScript
CauseNext compiles only its own folder
FixtranspilePackages in next.config
Lesson: source-only internal packages must be compiled by the app that uses them.
Interview line: "A monorepo lets shared types and config change in the same PR as the apps that use them. Each package has one job, so the AI layer can be tested without HTTP."
