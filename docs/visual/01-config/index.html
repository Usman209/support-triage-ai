Step 01

Configuration and secrets

Every setting and secret lives in .env. One file reads it, checks it, and gives the rest of the code a typed config object.

1. What happens when the app starts

Variables already in the environment win over .env, so production and CI can inject secrets without a file.

2. What Zod does to each value

In .env (always text) After Zod Why
API_PORT=3011 3011 (number) Ports are numbers, 1–65535
AGENT_REQUIRE_APPROVAL=true true (boolean) Only "true"/"false" allowed
LLM_PROVIDER=gemini error Must be anthropic | openai | ollama
COHERE_API_KEY= undefined Blank = not set (secrets optional for now)
RAG_TOP_K= error Settings are required: no hidden defaults in code

Problems and fixes

SymptomKEY= passed validation as ""
CauseAn empty string is still a string
FixblankToUndefined before validating
Lesson: normalise input first, then validate.
SymptomLANGFUSE_PUBLIC_KEY appeared twice
CauseCopy-paste; first copy empty
FixMerged into one line, values unchanged
Lesson: the last duplicate wins, so duplicates hide bugs.
SymptomInline # comments in .env read differently
CauseNode and Docker Compose parse .env differently
FixComments on their own line
Lesson: use the format every tool agrees on.
Interview line: "Config comes from the environment (12-factor). We validate it once at startup with Zod and fail fast, then the code uses one typed object. Secrets are never in git; in production they come from a secret manager."
