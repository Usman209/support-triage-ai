Docker: Postgres + MinIO

One command (pnpm infra:up) starts the database and file storage on your laptop, configured from the same .env.

Update (step 06): the app database is now PostgreSQL 18 installed on Windows. The Docker Postgres shown below is opt-in (pnpm infra:up:postgres-local). Why: port clash →

3. The startup race we hit (and fixed)

sequenceDiagram
  participant D as Docker
  participant M as MinIO container
  participant I as minio-init
  D->>M: start
  M->>M: Bitnami setup starts MinIO (temporary)
  D->>M: healthcheck
  M-->>D: healthy ✔
  D->>I: start (minio is healthy)
  M->>M: stop temporary MinIO
  I->>M: connect
  M-->>I: connection refused ✖
  M->>M: start real MinIO
  Note over I: Fix: retry loop until mc ready
  I->>M: retry connect
  M-->>I: OK ✔
  I->>M: buckets, policies, user

Problems and fixes

Symptompull access denied for minio/minio, 401 on quay.io
CauseMinIO stopped publishing community images
FixBitnami archive of release 2025-04-22
Lesson: pin versions and know your fallback. Archived images get no security updates: local dev only.
SymptomInit failed: connection refused although "healthy"
CauseImage restarts MinIO after its own setup
FixRetry loop in minio-init.sh
Lesson: healthy once does not mean ready now. Clients must retry.
SymptomAnyone could list all files in public
Cause"download" preset includes ListBucket
FixCustom policy: GetObject only
Lesson: test security with an anonymous request; don't trust a preset's name.
SymptomStarting only MinIO failed on Langfuse variables
CauseCompose checks variables in the whole file
FixGenerated all local passwords in .env
Lesson: Compose validates the entire file, not one service.
Interview line: "We use Postgres with pgvector, so tickets, approvals and embeddings live in one database with SQL joins and normal backups. Each service gets its own credentials with the minimum permissions, and setup scripts are idempotent."
