Step 06 · Task 3.1

RAG database tables (pgvector)

Where the knowledge base lives: help articles, their small chunks, and one embedding vector per chunk, with an index for fast "find the most similar" search.

1. The tables

erDiagram
  documents ||--o{ chunks : "has many (cascade delete)"
  documents {
    uuid id PK
    text source UK "file path, unique"
    text title
    text content_hash "skip re-embed if same"
    jsonb metadata
    timestamptz created_at
    timestamptz updated_at
  }
  chunks {
    uuid id PK
    uuid document_id FK
    int chunk_index "unique per document"
    text content
    int token_count
    vector embedding "vector(1536), HNSW cosine"
    jsonb metadata
    timestamptz created_at
  }

Problems and fixes

SymptomMigration "succeeded" but Docker Postgres had no tables
CauseTwo Postgres servers on port 5436; Windows one got the connection
FixUse Windows Postgres (your choice); Docker one opt-in
Lesson: "success" means success somewhere. Check current_database() and version().
SymptomNo CREATE EXTENSION vector in generated SQL
Causedrizzle-kit doesn't manage extensions
FixHand-written custom migration 0000
Lesson: hand-written DB setup still belongs in a versioned migration.
SymptomTest script: "top-level await not supported (cjs)"
CauseScript lived outside the project
FixMoved into repo: pnpm db:smoke
Lesson: useful checks belong in the repo.
Interview line: "Chunks and their embeddings live in Postgres with pgvector. Each chunk belongs to a document with cascade delete, so removed articles can't be retrieved. An HNSW index with cosine distance makes nearest-neighbour search fast, and the vector size comes from config so it always matches the embedding model."
