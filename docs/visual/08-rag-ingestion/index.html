Step 08 · Task 3.3

RAG ingestion: chunk, embed, store

16 help articles became 74 searchable chunks in Postgres. Re-running costs nothing for unchanged files, and deleted files disappear from search.

4. What we learned about the ticket data

Descriptions with {placeholders} 100% – Template-generated text
Subject "Refund request" → type "Refund request" 21% 20% Type label is random

Decision: don't score the AI against these labels. Build our own labelled test set in task 7.

Problems and fixes

SymptomTicket CSV in data/knowledge-base/
CauseThat folder is committed to git
FixMoved to data/raw/ (gitignored), verified with git check-ignore
Lesson: customer data in a committed folder = PII on GitHub.
SymptomDataset labels match only at chance level
CauseSynthetic dataset with random labels
FixOwn labelled test set in task 7
Lesson: check your data before trusting your metrics.
SymptomRisk of 429s on the free embedding tier
CauseFew requests per minute without a payment method
FixOne batched call; wait for Retry-After
Lesson: design for rate limits.
Interview line: "Ingestion is idempotent: each document has a fingerprint of its content, embedding model and chunk settings, so unchanged files cost nothing and a model change re-embeds everything. Chunks follow headings, overlap at boundaries and carry a 'Title > Section' header, and deleted articles are pruned so answers never cite stale content."
