Step 11 · Task 3.6

Langfuse tracing

Every chat request becomes a trace in Langfuse Cloud: retrieval, embedding, the exact prompt, the answer, tokens and time for each step.

1. One real trace

Surprise from real data: the embedding call (1.5 s) was slower than the LLM (0.8 s). That's why the query cache matters.

3. What you can do with traces

Debug a bad answer

Click "view trace ↗" in the chat, open llm.groq, read the exact prompt and sources.

Find knowledge gaps

Filter level WARNING = "not found" questions.

Find slow steps

Timing per observation: retrieval vs LLM.

Compare prompts

Every trace is tagged with the prompt version (answer-v2).

4. When the backend is down

sequenceDiagram
  participant U as User
  participant A as API

  A-->>U: answer (always)
  A--xL: export spans (Langfuse unreachable)
  Note over A,L: trace lost, request unaffected (best effort)
  U->>A: next question
  A-->>U: answer
  A->>L: export spans
  L-->>A: ok, trace visible
