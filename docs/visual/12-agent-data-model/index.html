Step 12 · Task 4.1

Agent data model

Tickets, agent runs, proposed actions (the approval queue) and an audit log that nobody can edit, built before the agent itself.

1. The tables

erDiagram
  tickets ||--o{ agent_runs : "triaged by"
  agent_runs ||--o{ proposed_actions : "proposes"
  tickets ||--o{ proposed_actions : "for"
  tickets {
    uuid id PK
    text external_id UK "CSV Ticket ID"
    text subject
    text description
    text product
    enum category "null until approved"
    enum priority "null until approved"
    enum status
  }
  agent_runs {
    uuid id PK
    uuid ticket_id FK
    enum status "running|completed|failed"
    text model
    text prompt_version
    text trace_id "Langfuse"
    jsonb result "suggestion"
  }
  proposed_actions {
    uuid id PK
    uuid run_id FK
    uuid ticket_id FK
    enum type "5 allowed types"
    jsonb payload
    text rationale "why"
    enum status "pending..."
    timestamptz expires_at
    text decided_by
  }
  audit_log {
    bigserial id PK "ordered"
    timestamptz occurred_at
    text actor "agent|user|system"
    text event
    uuid ticket_id "NO foreign key"
    jsonb details
  }

No customer name, email, age or gender anywhere: not needed to triage, so not stored.

2. Life of a proposed action

stateDiagram-v2
  [*] --> pending: agent proposes
  pending --> approved: human approves
  pending --> rejected: human rejects
  pending --> expired: after 30 min
  approved --> executed: action runs
  approved --> failed: action errors
  rejected --> [*]
  expired --> [*]
  executed --> [*]
  failed --> [*]

Every arrow also writes a row to audit_log.

Problems and fixes

SymptomDrizzle can't express "append-only"
CauseORMs model tables, not triggers
FixHand-written migration with triggers
Lesson: rules that must always hold belong in the database.
SymptomTesting a failing statement aborted the transaction
CausePostgres aborts a transaction after any error
FixSAVEPOINT (nested transaction) per expected failure
Lesson: savepoints let you test errors inside one transaction.
Symptomdb:smoke: "74 chunks left after cascade"
CauseTest counted all chunks, including the real knowledge base
FixCount only the test document's chunks
Lesson: tests must not depend on other data in the database.
Interview line: "The agent can only propose: proposals are rows with a type from an allow-list, a rationale, a status and an expiry. A human approves, only then does the action run, and every step goes to an audit log that the database itself makes append-only."
