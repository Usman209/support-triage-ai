Approvals: the human decides

Review what the agent proposed at /approvals. Approve, edit or reject. Approving executes the action on the ticket, safely and audited.

2. What happens when you click Approve

sequenceDiagram
  participant U as Reviewer
  participant W as Next.js proxy
  participant A as API
  participant D as Postgres
  U->>W: Approve (edited payload?)
  W->>A: POST /approvals/:id/approve
  A->>D: BEGIN
  A->>D: UPDATE … SET approved WHERE pending AND not expired
  alt no row claimed
    A-->>U: 404 / 409 expired / 409 already decided
  else claimed
    A->>A: Zod-validate payload (400 → ROLLBACK, stays pending)
    A->>D: audit action.approved (edited? original?)
    A->>D: SAVEPOINT: apply to ticket
    alt ok
      A->>D: executed + result · audit action.executed
    else error
      A->>D: failed + error · audit action.failed
    end
    A->>D: COMMIT
    A-->>U: item + ticket after the change
  end

3. Two reviewers click at the same moment

sequenceDiagram
  participant Al as Alice
  participant Bo as Bob
  participant D as Postgres
  Al->>D: UPDATE … WHERE id = X AND status = 'pending'
  Bo->>D: UPDATE … WHERE id = X AND status = 'pending'
  D-->>Al: 1 row (wins) → executed
  D-->>Bo: 0 rows → 409 "Already executed by user:alice"

Tested for real: 200 + 409, winner user:alice.

4. Tested rules

Check Result
Approve → executed, ticket changed pass
Approve twice 409 already decided
Invalid edit (free_pizza) 400, stays pending
Valid edit executed with edit
Simultaneous approvals 200 + 409
Reject rejected
Expired proposal 409 expired
Through the web proxy (the buttons) priority null → medium

Problems and fixes

SymptomBrowser needs constants from @sta/shared
CauseThat package also contains config.ts (reads .env)
Fix@sta/shared/client browser-safe entry
Lesson: separate server-only and browser-safe modules.
SymptomTwo approvals at once could both execute
CauseRead-then-write race
FixAtomic conditional UPDATE
Lesson: let the database decide races.
SymptomSame ticket, different priority on re-run
CauseLLM output is non-deterministic
FixHuman approval; evals run multiple times
Lesson: measure variance, don't trust one run.
Interview line: "Approval is an atomic claim on a pending, unexpired proposal, followed by re-validation of the possibly edited payload and execution in the same transaction, with every step in an append-only audit log. Two reviewers clicking at once get one success and one 409."
